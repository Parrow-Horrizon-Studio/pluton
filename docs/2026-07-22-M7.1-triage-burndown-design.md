# M7.1 — Triage & Burn-Down — Design Spec

**Milestone:** M7.1, the first sub-milestone of the new **Phase 2.5 — Parity & Polish**, inserted between M7 (Architecture-specific tools, complete at v0.2.5) and M8 (Plugin system).

**Goal:** Put the codebase on a clean, verified footing before the UI and parity work that follows — close what is already done, fix every confirmed bug, retire the lint debt permanently, modernize CI ahead of a hard deadline, and leave every remaining open issue assigned to a named milestone. Ship as **v0.3.0**.

**One-line summary:** Turn 91 accumulated issues — a third of them stale or ignorable — into 49 that are all real, sized, and scheduled.

**Arithmetic:** M7.1 closes **42** issues (7 already-done + 10 behavior + 2 completions + 3 lint/format + 1 CI + 3 real debt + 16 batched debt), leaving exactly the **49** feature gaps, each assigned to a named later milestone.

## Context: why this milestone exists

M0–M7 built the modeler; M7 shipped the last of the architecture tools. The roadmap went straight from there to M8 (plugins) and M9 (Mac + installers, the public-beta line). Two problems with that:

- **91 open issues had accumulated** with no triage pass. Some described features that had already shipped; some were real bugs nobody had scheduled.
- **The app has no toolbar, no icons, and no cursors.** Every one of its 18 tools is reachable only by keyboard shortcut or a menu. Shipping that to beta users as a "SketchUp-like modeler" would not land.

Phase 2.5 addresses both. M7.1 is its foundation: fix and clean, so the UI work (M7.2/M7.3), new tools (M7.4), materials (M7.5), and interaction parity (M7.6) build on something solid rather than compounding the debt.

## Triage result (the input to this spec)

All 91 open issues were verified against the current code, not judged from titles:

| Bucket | Count | Disposition |
|---|---|---|
| Already done, never closed | 7 | Close in M7.1 with evidence |
| Confirmed bugs | 8 | Fix in M7.1 |
| Partially done | 2 | Complete in M7.1 |
| Tech debt / test / CI | 25 | Nearly all in M7.1 |
| Feature gaps / enhancements | 49 | **Scheduled** to M7.2–M7.6, M10, M12+ |

**Scheduled is not deferred.** The 49 remaining are assigned to named milestones — icons/toolbar to M7.2, materials to M7.5, inferencing and guides to M7.6, the performance charter (#16, #23, #30, #24) to M10, #18 to M12+. Nothing is left rotting.

## Global Constraints

- **Ship as v0.3.0.** Phase 2.5 uses **minor** bumps per sub-milestone (M7.1→v0.3.0 … M7.6→v0.8.0), which pushes M8→v0.9.0, M9→v0.10.0, M10→v0.11.0, M11→v1.0.0. v1.0 still lands at the end of Phase 4 as intended, but the roadmap's stated per-phase version ranges are now wrong and **must be relabelled as part of this milestone**.
- **Full-stack milestone.** Unlike M4–M7 (Python-only, `ctest` frozen at 79/79), M7.1 touches the C++ kernel (#19). `ctest` will grow past 79.
- **Every behavior fix ships with a regression test that provably fails before the fix.** Not merely "a test exists" — for the subtler fixes the test must be demonstrated to go red when the fix is reverted.
- **The lint sweeps are behavior-neutral.** The full suite passing is the proof; no test may be weakened or deleted to accommodate a sweep.
- **Lint sweeps land before any behavior fix**, each as its own mechanical commit, with both SHAs recorded in `.git-blame-ignore-revs`.
- **The CI lint gate is enabled immediately after the sweeps**, not at the end, so the rest of the milestone is held to it.
- **End-state gates:** full `pytest` green (currently 1027, will grow); `ctest` green (79 + new); `ruff check python/pluton` = **0**; `ruff format --check` clean; C++ clang-format clean; CI green on ubuntu-24.04 and windows-2022.
- **Git discipline:** work on `main`; never `git add -A`/`.`; never `--no-verify`, `--amend`, or `--no-gpg-sign`; commit trailer `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`.
- **Build/test with `.venv/Scripts/python` explicitly.**

### 1.2 Behavior fixes (9)

The 8 confirmed bugs plus #95:

| Issue | Defect |
|---|---|
| **#57** + **#47** | `ScaleTool._cursor_world` hardcodes the cursor-plane normal to world-Z — wrong in any rotated context. Same root cause as #47's missing axis-aware dragging; fixed together. |
| **#56** | `ExplodeInstanceCommand.do()` reparents children into `parent.children` but never removes them from `defn.children` → double ownership for multi-instance Components. |
| **#58** | `Model.pick_instance` uses `ray_pick_face` only → edge-only groups/components are unpickable. |
| **#46** | `_on_after_undo_redo` unconditionally clears the selection → selection lost across transform undo/redo. |
| **#49** | `RotateTool._effective_normal` re-derives from the last forced axis rather than the original inferred normal → auto-tilt never restored when cycling back. |
| **#89** | `_set_units_metric`/`_set_units_imperial` don't call `_refresh_tool_options()` → Wall options-bar fields go stale on a mid-tool unit change. |
| **#97** | `_on_reorder_view` calls `execute()` unconditionally → a clamped no-op reorder dirties the document and pushes an inert undo entry. |
| **#95** | Annotations render/select only in the active editing context — a dimension added inside a group vanishes when you exit it. |
| **#19** | `HalfEdgeMesh::clear()` shrinks the slabs instead of tombstoning → `restore_*` after a clear throws. **Kernel.** |

**Resolution for #95** (a design decision, settled here): annotations **render from all contexts, dimmed when not active**, while **selection and picking remain active-context-only**. This matches how geometry already behaves — dimmed faces in a non-active group are visible but you select the group, not the face — so it is internally consistent, and it matches SketchUp, where a dimension inside a group stays visible from outside.

## Section 2 — Sequencing

Order is load-bearing, not cosmetic. A repo-wide `ruff format` rewrites 66 files; if behavior fixes land in those files first, every fix is re-touched and its diff becomes unreadable.

1. **Triage closures** — close the 7, comment the evidence. No code.
2. **Python lint sweep** — noqa + E501 + `ruff format`, isolated mechanical commits.
3. **C++ format sweep** — `.clang-format` + `cpp/` sweep, its own commit.
4. **`.git-blame-ignore-revs`** — record both sweep SHAs.
5. **CI modernization + lint gate** — actions bump, C4702, gate enabled. From here the rest of the milestone is gated.
6. **Behavior fixes** — the 9, on a clean, gated base.
7. **Completions** — #47, #55, #96.
8. **Real debt** — #59, #84, #20.
9. **Batched small debt** — the ~17.
10. **Docs + release v0.3.0.**

Alternatives considered: *fix-first-then-clean* (bug diffs read cleanly, but the sweep then rewrites those exact lines again) and *clean-each-file-as-touched* (minimal churn, but leaves most of the 213 findings and the gate can never be switched on). Clean-first wins because the sweep is verifiable — it alters no behavior, so a green suite proves it — and because it lets the gate protect the rest of the milestone.

## Section 3 — Testing strategy

**Behavior fixes — the bar is a test that provably fails before the fix.** For each of the 9, write the regression test first, confirm it goes red against current code, then fix. For the subtler ones (#46 selection-across-undo, #56 explode ownership, #95 render scope) the implementer must revert the fix, observe the test fail, and restore — and report that observation. M7e justified this discipline twice: Task 6's animation-leak fix and Task 7's undo-guard tests both looked complete but did not actually catch their target regression until proven.

**Lint sweeps — behavior-neutral, so the suite is the proof.** No test may be modified to accommodate a sweep. Additionally assert `ruff check python/pluton` = 0 and `ruff format --check` clean.

**#19 (kernel)** — new GoogleTests covering `clear()` followed by `restore_*`; `ctest` moves off 79/79.

**#84 (security)** — hostile-input fixtures: truncated files, oversized declared counts, malformed buffer offsets. Each must raise a clean `PlutonIOError`, never crash the process.

**#59** — a test proving GL buffers are released when a definition is deleted or exploded.

**#20** — whichever way it resolves, the resolution is recorded: a fix plus test, or a documented conclusion in the issue explaining why the warnings are benign.

**End-state gates:** `pytest` green (1027 +new); `ctest` green (79 +new); `ruff check` = 0; `ruff format --check` clean; clang-format clean; CI green on both platforms; `_core.version()` == `0.3.0`.

## Decisions log

- **D1 — Full lint clean + CI gate**, not a scoped or new-code-only gate. One-time mechanical cost; permanently retires the #48 per-milestone tax; cheapest now, before M7.2/M7.3 add many new files.
- **D2 — M7.1 is full-stack.** #19 is included even though it is the only kernel item, because fixing foundational kernel correctness while the kernel is quiet is cheaper than during M10's active churn.
- **D3 — Minor version bumps per sub-milestone** (M7.1 = v0.3.0). Preserves the per-milestone CI-verified release cadence that has caught cross-platform breaks every milestone; the roadmap's version labels are updated to match.
- **D4 — Annotations render from all contexts (dimmed), select only in the active one.** Consistent with geometry's existing behavior and with SketchUp.
- **D5 — Nothing is deferred for convenience.** Items previously set aside (#20, #95, clang-format, #47, #55, #96, #15, #17, #41, #61) are all in scope. The only exclusions are feature gaps already assigned to named later milestones.
- **D6 — Clean before fix**, with sweep SHAs in `.git-blame-ignore-revs`.

## Risks

- **#20 is unsized.** The investigation could be short or could uncover a real binding-lifetime bug. It is included deliberately; if it proves deep it will be surfaced at that point rather than silently consuming the milestone.
- **The format sweeps produce a large diff.** Mitigated by isolation (own commits, no behavior change, green suite as proof) and `.git-blame-ignore-revs`.
- **#19 changes the kernel and lengthens CI.** Expected and accepted; `ctest` count moves off its long-held 79.
