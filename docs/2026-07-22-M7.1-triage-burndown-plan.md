### Task 6: Fix the Scale cursor plane + axis-aware dragging (#57, #47)

**Files:**
- Modify: `python/pluton/tools/scale_tool.py` (`_cursor_world`, ~line 387)
- Test: `tests/test_scale_tool_cursor_plane.py` (new)

**The defect.** `_cursor_world` intersects the cursor ray with a plane whose normal is hardcoded to world-Z:

```python
n = np.array([0, 0, 1], np.float32)      # scale_tool.py:403
```

In a rotated editing context (or any view that isn't roughly top-down) that plane is wrong, so the grip does not follow the cursor. Its own docstring still says *"M4d refines with axis-aware dragging"* — a stale note referencing a milestone that shipped long ago; delete it as part of the fix.

**The fix, in two parts:**

1. **Bug (#57): use a camera-facing plane, not world-Z.** A plane through the grip whose normal is the camera's view direction is correct in *every* orientation and can never be parallel to the cursor ray:

   ```python
   view_dir = self._camera.position - self._camera.target
   n = view_dir / np.linalg.norm(view_dir)
   ```

2. **Enhancement (#47): axis-aware dragging.** When the active grip constrains a single axis, don't use a plane at all — project the cursor ray onto the grip's axis line and take the closest point. Standard ray/line closest-point:

   ```python
   def _closest_point_on_axis(p0, axis_dir, origin, direction):
       """Point on the line (p0 + t*axis_dir) closest to the ray (origin + s*direction)."""
       u = np.asarray(axis_dir, np.float64)
       d = np.asarray(direction, np.float64)
       w0 = np.asarray(p0, np.float64) - np.asarray(origin, np.float64)
       a, b, c = float(u @ u), float(u @ d), float(d @ d)
       dd, e = float(u @ w0), float(d @ w0)
       denom = a * c - b * b
       if abs(denom) < 1e-12:            # ray parallel to the axis
           return np.asarray(p0, np.float64)
       t = (b * e - c * dd) / denom
       return np.asarray(p0, np.float64) + u * t
   ```

**Before writing code, read `_factor_vec_for` and the grip definitions in `scale_tool.py`** to learn how a grip records which axes it constrains. Use that to decide per-drag between the axis projection (single-axis grip) and the camera-facing plane (corner/uniform grip). Keep the existing world→local conversion at the end of `_cursor_world` exactly as it is — only how the *world* cursor point is computed changes.

### Task 7: Fix Explode double-ownership (#56)

**Files:**
- Modify: `python/pluton/commands/explode_command.py`
- Test: `tests/test_explode_multi_instance.py` (new)

**The defect.** `ExplodeInstanceCommand.do()` reparents the exploded instance's children into the parent but never removes them from the source definition:

```python
self._child_records = list(defn.children)
for child in defn.children:
    child.transform = t @ child.transform
    self._parent.children.append(child)          # appended to parent...
                                                 # ...but never removed from defn.children
```

For a Component placed **more than once**, every other instance of that definition still lists those children — so the same child objects are now owned twice and render/pick in both places. Undo must restore them to `defn.children` exactly as they were.

- [ ] **Step 1: Write the failing test** — `tests/test_explode_multi_instance.py`:

```python
import numpy as np

from pluton.commands.command_stack import CommandStack
from pluton.commands.explode_command import ExplodeInstanceCommand
from pluton.model.model import Model


def test_explode_removes_children_from_source_definition():
    model = Model()
    # A component definition that itself contains one child instance.
    inner = model.new_definition("Inner", is_group=False)
    comp = model.new_definition("Comp", is_group=False)
    comp.children.append(model.new_instance(inner, np.eye(4, dtype=np.float64)))

    # Place the SAME component twice in the root.
    a = model.new_instance(comp, np.eye(4, dtype=np.float64))
    b = model.new_instance(comp, np.eye(4, dtype=np.float64))
    model.root.children.extend([a, b])
    assert len(comp.children) == 1

    stack = CommandStack()
    stack.execute(ExplodeInstanceCommand(model.root, a), model)

    # The child moved to the root; the definition must no longer own it,
    # otherwise instance `b` still renders it too (double ownership).
    assert len(comp.children) == 0
    assert len(model.root.children) == 2      # b + the reparented child


def test_explode_undo_restores_children_to_the_definition():
    model = Model()
    inner = model.new_definition("Inner", is_group=False)
    comp = model.new_definition("Comp", is_group=False)
    child = model.new_instance(inner, np.eye(4, dtype=np.float64))
    comp.children.append(child)
    a = model.new_instance(comp, np.eye(4, dtype=np.float64))
    model.root.children.append(a)

    stack = CommandStack()
    stack.execute(ExplodeInstanceCommand(model.root, a), model)
    stack.undo()

    assert comp.children == [child]
    assert a in model.root.children
```

### Task 14: Tombstone `HalfEdgeMesh::clear()` (#19) — KERNEL

**Files:**
- Modify: `cpp/src/halfedge.cpp` (`clear()`, line 313)
- Test: the existing half-edge GoogleTest file under `cpp/tests/` (find it with `ls cpp/tests/`)

**The defect.** `clear()` shrinks the slabs, destroying id addressability:

```cpp
void HalfEdgeMesh::clear() noexcept {
    vertices_.clear();
    halfedges_.clear();
    faces_.clear();
    position_index_.clear();
    edge_index_.clear();
    dirty_ = true;
}
```

Every other removal in this mesh **tombstones** (sets `alive = false`) so that ids stay valid and `restore_*` can revive them — that is how undo works. `clear()` breaks the invariant: after it, `restore_*` throws because the slot no longer exists.

**The fix.** Tombstone instead of shrinking. Keep the slabs at their current size so ids remain addressable; only the lookup indices are truly emptied:

```cpp
void HalfEdgeMesh::clear() noexcept {
    for (auto& v : vertices_) v.alive = false;
    for (auto& h : halfedges_) h.alive = false;
    for (auto& f : faces_) f.alive = false;
    position_index_.clear();
    edge_index_.clear();
    dirty_ = true;
}
```

Memory is intentionally not reclaimed — that is what issue #16 (slab compaction, chartered to M10) is for. Note this in a comment so the next reader does not "fix" it back.
