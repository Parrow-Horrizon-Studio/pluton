# M7.4: Geometry tools

**Status:** approved, not yet planned
**Milestone:** M7.4 (follows M7.3, shipped v0.5.0)
**Target version:** 0.6.0

## Context

M7.3 finished the shell. The right edge is one panel, tools have a home for
their settings, and the model carries per-instance name and hidden state. What
the application still lacks is geometry: eighteen tools can draw, transform and
annotate, but only Push/Pull creates new surface from old, and nothing generates
a shape from numbers.

The roadmap line for M7.4 reads "additional SketchUp-standard tools plus basic
geometry primitives". Taken at face value that spans five independent clusters
(face and edge operations, primitives, draw variants, camera tools, section
planes) which is more than one milestone. This spec covers the geometry half.
The breadth half (four draw variants, three camera tools, numeric transform
fields, and the M7.3 follow-ups in #105) goes to M7.5.

The split is not arbitrary. Offset, Follow Me and the primitives all change what
geometry exists. The draw variants and camera tools do not, and they share no
machinery with these, so putting them in one spec would join them by calendar
rather than by substance.

## 1. Scope

### 1.1 What ships

Two geometry operations, four primitives, and the debt that sits underneath
them:

| Item | Layer | Shortcut |
|---|---|---|
| Offset | Python | `F` |
| Follow Me | Python | none |
| Box | C++ generation, Python tool | none |
| Cylinder | C++ generation, Python tool | none |
| Cone | C++ generation, Python tool | none |
| Sphere | C++ generation, Python tool | none |

Plus `#26` (`Scene.edge_between` and the `DissolveEdgeCommand` refactor), `#60`
(`ScaleTool` extraction and the append-guard sweep), and one sub-item of `#92`
(the `pick_face_local` inverse-transpose normal).

### 1.2 The layering rule

The codebase already answers where geometry work belongs, and this milestone
follows it rather than inventing a second convention.

**C++ generates geometry from parameters.** `cpp/include/pluton/primitives.h`
holds `make_cube(float size = 1.0f)`, bound at `cpp/bindings/module.cpp:98`,
exported from `python/pluton/__init__.py:3`, and covered by
`cpp/tests/test_primitives.cpp`. The three new primitives join it there as pure
functions returning a `Mesh`, with no undo concerns because they mutate nothing.

**Python transforms geometry that exists.** Push/Pull, which is a sweep along a
straight path, composes `AddVertexCommand`, `AddEdgeCommand` and
`AddFaceCommand` into one `CompositeCommand` and pushes it with
`push_executed(composite, scene)`. Undo falls out of the primitive commands with
no extra machinery. Offset and Follow Me do the same.

The dividing line: C++ makes geometry from numbers, Python reshapes geometry
that is already there.

**Consequence, stated plainly:** `ctest` moves off 82/82 for the first time since
M7.1. That is the point of putting tessellation in the kernel, not an accident to
be worked around.

### 1.3 Shortcuts

Taken single keys today: `A B C D E G H I L M N O P Q R S T W` and `Space`,
plus `Ctrl` combinations, `Del`, `Shift+H` and `Shift+Z`. Free: `F J K U V X Y Z`.

Offset takes `F`, matching SketchUp. Follow Me and the four primitives get menu
and toolbar entries with no shortcut: Follow Me has no SketchUp convention to
match, and primitives are placed rarely enough that a key is poor value.

This is deliberate conservation. M7.5 wants seven more tools (four draw variants,
three camera) and seven keys would remain. Spending six here would force a chord
scheme there, which is a change to M7.2's action registry that neither milestone
has budgeted.

### 1.4 The shared sweep layer

Push/Pull, Offset and Follow Me are the same operation with different
destinations:

| Tool | Source loop | Destination loop |
|---|---|---|
| Push/Pull | face boundary | same loop displaced along the face normal |
| Offset | face boundary | same loop displaced along angle bisectors, in plane |
| Follow Me | profile boundary | profile transformed to each path station |

`push_pull_tool.py:318` (`_commit_extrusion`) already performs the shared part:
create one matching vertex per source vertex, then zip the two loops into side
faces. A new Qt-free `python/pluton/tools/sweep_support.py` holds it:

```python
def loft_between_loops(
    scene, src_loop_vids, dst_positions, *, cap_start: bool, cap_end: bool
) -> list[Command]

def offset_polygon(points, normal, distance) -> tuple[np.ndarray, float]

def sweep_stations(
    profile_loop, path_points, *, closed: bool
) -> list[np.ndarray]   # 4x4 transforms, one per station
```

`cap_start` and `cap_end` are two flags rather than one, because the three callers
need three different answers: Push/Pull caps the far end always and the near end
only when `_should_add_bottom_cap` says so, Follow Me caps both ends of an open
path, and a closed path caps neither. A single boolean cannot express that.

`offset_polygon` returns the clamped distance alongside the points, so a tool can
render the drag stopping at the limit without computing that limit twice.

`sweep_stations` returns 4x4 transforms, not positions. Each station must orient
the profile as well as place it, since the mitered plane at a corner is tilted
relative to both adjoining path segments.

Three existing problems resolve here rather than being fixed separately:

1. **`Scene.edge_between(v1_id, v2_id) -> int | None`** (`#26`), public and
   non-mutating. The stitcher needs to know whether an edge already joins two
   loop vertices, which is the use case `#26` was filed for.
2. **`DissolveEdgeCommand` loses its `scene._mesh` reach-in** (`#26`), because
   `_seam_merge_pass` (`push_pull_tool.py:299`) is part of what moves.
3. **The `# type: ignore[attr-defined]` at `push_pull_tool.py:357` disappears.**
   The current code reads `c._vertex_id` off a command object to learn which
   vertex it created. `loft_between_loops` returns ids properly.

**Sequencing requirement, not a preference:** the extraction and the Push/Pull
migration land as the first task, before any new tool exists, gated by
Push/Pull's current tests. The change is behaviour-preserving. If it is wrong it
fails alone, rather than being discovered three tools later with new work stacked
on it.

### 1.5 Offset

Click a face, drag to set the distance, click to commit. Typed entry goes through
`Tool.apply_typed_value(text, units) -> bool`, which the tool protocol already
provides. Faces only: a coplanar edge loop with no face is a second result shape
with its own edge cases, and it is not what the tool is reached for.

No option bar, matching SketchUp, so the Tool Settings tab does not auto-switch
when Offset is armed.

The algorithm over the existing Scene API:

1. `face_loop(f_id)` for the ordered vertex ids, `face_normal(f_id)` for the plane
2. `offset_polygon` displaces each vertex along its angle bisector, scaled by
   `1 / sin(theta / 2)`, so offset edges stay parallel to their originals at the
   requested distance
3. Remove the source face, add the new loop's vertices and edges, stitch the ring
   with `loft_between_loops`, add the inner face

**Clamping.** Offsetting inward eventually collapses the polygon. The general
case (concave loops, straight-skeleton collapse events) is a research problem
and is not attempted. Instead:

- Compute an analytic per-edge collapse limit, the distance at which an edge's
  two offset endpoints coincide, and take the minimum across edges. This is exact
  for the common cases, including a rectangle collapsing at half its short side.
- Validate that the polygon at that distance is simple. If it self-intersects
  anyway, which remains possible on concave loops, binary search downward with a
  fixed iteration cap.

The drag visibly stops at the limit and cannot produce broken geometry. On a
pathological concave face it may stop slightly short of the true maximum. That is
a stated limitation, not a defect to be discovered later.

### 1.6 Follow Me

Select the path edges with Select, activate Follow Me, click the profile face.
Preselection makes the path unambiguous before the sweep starts, and matches what
SketchUp users already have in their hands.

1. **Order the selection into a chain.** The selected edges arrive as a set. The
   tool walks them into an ordered path and detects whether the path closes.
2. **Compute stations.** At each interior path vertex the profile plane is the
   bisector of the incoming and outgoing directions. That bisector is what makes
   corners miter rather than gap.
3. **Loft consecutive stations** with `loft_between_loops`. Open paths get end
   caps. Closed paths join the last station to the first and get none, which is
   what produces a lathe from a closed profile path.

**Self-intersection is refused, not repaired.** Repairing overlapping sweep
geometry at tight corners is the genuinely hard research problem here and would
consume the milestone. Detection is one comparison: if the mitered transform
inverts the profile's signed area, the corner is too tight for that profile. The
tool reports this in the status bar and emits nothing.

### 1.7 Primitives

`cpp/include/pluton/primitives.h` grows three functions:

```cpp
Mesh make_box(float width, float depth, float height);
Mesh make_cylinder(float radius, float height, int segments);
Mesh make_cone(float radius, float height, int segments);
Mesh make_sphere(float radius, int rings, int segments);
```

`make_cube(float size)` is kept and reimplemented as `make_box(size, size, size)`.
Its existing GoogleTests keep passing unchanged, and
`python/pluton/__init__.py`'s export does not break.

**Python side.** One `PrimitiveTool` base carries the shared two-stage gesture:
drag the base footprint, then move for height. Each subclass supplies a mesh
factory and its option fields. Segment and ring counts live in the Tool Settings
tab, so these four do trigger M7.3's auto-switch, unlike Offset.

**Geometry is one-shot.** The result is ordinary editable geometry. The instance
does not remember that it was a cylinder with N segments, because a parametric
definition would need a model concept that does not exist, plus persistence and a
regeneration command. Segment count is chosen before creation and baked in.

**Placement** is loose geometry in the active context, consistent with every other
draw tool. Grouping is left to the user rather than decided for them.

### 1.8 Debt that is load-bearing

**`#26`** is absorbed into 1.4 above.

**`#92`, the `pick_face_local` normal.** `python/pluton/model/model.py:170-178`
documents its own limitation: the normal uses the instance transform's linear
block, so it is exact only for rigid transforms, and the docstring names the fix
as the inverse-transpose of that block. This matters directly here, because a
primitive placed inside a non-uniformly scaled group would otherwise pick the
wrong faces.

**`#60`.** `ScaleTool._world_transform` exists at
`python/pluton/tools/scale_tool.py:86`; `_lift_local_to_world` does not yet and
is the extraction to make, with a None-guard on `_world_transform`. The
accompanying defensive append-guard sweep covers
`group_commands.py:90` (`MakeGroupCommand._redo`), and
`instance_commands.py` (`CreateInstanceCommand.do`,
`DeleteInstanceCommand.undo`).

### 1.9 Tool Settings integration

`ToolSettingsPage.add_bar` has three call sites today and no guard against being
called twice with the same key: a second call would overwrite the key-to-index
mapping and orphan the first widget in the stack. This was recorded as a Minor
during M7.3 review and deferred because three fixed call sites made it
theoretical.

Going to seven bars is where it stops being theoretical, so the guard lands here
rather than staying in `#105`.

## 3. Testing

**Pure and headless, no `QApplication`:**

- `offset_polygon`: parallel offset edges at a given distance; the analytic
  collapse limit on a rectangle equals half its short side; a concave loop whose
  analytic limit still self-intersects gets binary-searched to a simple polygon
- `sweep_stations`: bisector planes at corners; closed paths join last to first;
  a corner tight enough to invert the profile's signed area is reported
- `loft_between_loops`: ring face count equals loop length; caps present when
  requested and absent when not
- `Scene.edge_between`: existing edge found in both vertex orders, `None` when
  absent

**C++ GoogleTests, one per primitive:** vertex and face counts for a given
segment count, watertightness, outward-facing normals, and `make_cube(s)`
producing what `make_box(s, s, s)` produces.

**Qt:** each of the six tools for gesture, undo and redo, and typed value where
supported. Push/Pull's existing tests gate the 1.4 migration unchanged.

**Regression:** the full Python suite green plain and under `CI=true`, and
`ctest` green at its new count.

**One tripwire.** `tests/test_icon_assets.py:91` asserts `len(declared) == 29`.
Six new tools carry `ActionSpec` icons, so that becomes 35. Unlike M7.3's panel
icons, these are command icons, so `panel_icons.NON_ACTION_ICONS` is not the
mechanism and must not be used. The count is updated in the same task the first
icon lands, or that task fails.

## 4. Decisions

**D1. Offset and Follow Me are Python, not kernel operations.** Push/Pull is the
same class of operation and is already Python, composing primitive commands.
Undo falls out for free, tests need no rebuild, and one idiom covers all three
tools.

**D2. Primitives are C++.** `make_cube` already lives in `primitives.h` with
GoogleTests. Tessellation loops belong in the compiled layer, and pure generation
functions have no undo concerns to complicate the choice.

**D3. Primitives produce one-shot geometry.** Parametric definitions would need a
model concept, persistence and a regeneration command, for a capability nobody
has asked for.

**D4. Offset works on faces only.** Coplanar edge loops are a second result shape
with their own edge cases and roughly double the tests.

**D5. Offset clamps rather than rejecting.** The drag stops at the limit, so
broken geometry is unreachable and there is no error state to design.

**D6. Follow Me preselects the path.** Unambiguous before the sweep starts, and
it matches SketchUp muscle memory. Drag-to-trace is ambiguous at branching edges.

**D7. Follow Me refuses self-intersecting sweeps.** Detection is a signed-area
inversion check. Repair is a research problem and would consume the milestone.

**D8. The shared layer is extracted and Push/Pull migrated onto it.** Leaving
Push/Pull on its own copy would ship the duplication that M7.3's reviews flagged
repeatedly. A general N-loop sweep framework would be speculative generality for
two callers.

**D9. Primitives get no shortcuts.** Conserves six of eight free keys for M7.5's
seven tools, avoiding a chord-scheme redesign that neither milestone budgeted.

**D10. Two `#92` sub-items are deferred rather than included.** Cross-session
`opening_definitions` dedup persistence (`opening_commands.py:35,47`) and
`CreateWallCommand` bookkeeping alignment have nothing to do with geometry tools.
They are in the M7.4 bucket because a triage pass put them there. Carrying them
would pad the milestone without making it more coherent.

## 5. Out of scope

- **Draw variants** (2-point arc, rotated rectangle, pie, freehand), to M7.5
- **Camera tools** (Position Camera, Look Around, Walk), to M7.5. No geometry, no
  commands, no undo: they share nothing with this milestone
- **Numeric transform fields** in Entity Info, to M7.5, still blocked on the 4x4
  decomposition ambiguity M7.3 identified
- **`#105`**, the M7.3 follow-ups, to M7.5, except the `add_bar` guard in 1.9
- **Section planes.** A Section Plane entity, live renderer clipping and
  per-scene section state. Milestone-sized on its own and entangled with M12
- **Drawing axes.** Repositioning them touches every tool's coordinate handling
  and the inference engine
- **Offset on edge loops** (D4)
- **Self-intersection repair** in Follow Me (D7)
- **Parametric primitives** (D3)

## 6. Risks

- **Migrating Push/Pull is the highest risk**, because it is shipped, tested and
  in daily use. Mitigation: it is the first task, lands alone, is
  behaviour-preserving, and its existing tests gate it. A failure there is
  isolated rather than discovered under three new tools.
- **Offset clamping on concave faces** is approximate by design. Mitigation:
  analytic limit, then simple-polygon validation with a bounded binary search,
  and the residual limitation stated in 1.5 rather than left to be found.
- **Follow Me miters** are the hardest maths in the milestone. Mitigation: scope
  excludes self-intersection repair, and the signed-area inversion test converts
  the hard case into a refusal.
- **First C++ change since M7.1.** `ctest` moves off 82/82 deliberately. Local
  runs need the MSVC `vcvars64` environment invoked through a `.bat` wrapper:
  passing that path through shell quoting silently no-ops and exits 0, which
  looks like a pass and proves nothing.
- **The icon count guard** (section 3) fails the moment the first new icon lands
  unless updated in the same task.

## 7. Sequencing

Eight phases, not eight tasks. Task decomposition belongs to the implementation
plan; several of these phases carry more than one task.

1. `sweep_support` extraction, `Scene.edge_between`, `DissolveEdgeCommand`
   refactor, Push/Pull migration
2. Offset tool, including `offset_polygon` clamping
3. Follow Me: path ordering, stations, miters, refusal
4. C++ `make_box` / `make_cylinder` / `make_cone` / `make_sphere`, bindings,
   GoogleTests, `make_cube` reimplemented
5. `PrimitiveTool` base and the four subclasses
6. Icons, actions, cursors, the icon-count guard, the `add_bar` duplicate-key
   guard
7. `#60` extraction and append-guard sweep, `#92` inverse-transpose normal
8. Regression both ways, `ctest`, docs, v0.6.0 release

Roughly fourteen to eighteen tasks, comparable to M7.3's sixteen.
