# M7.3 — Outliner & Properties Panel (Design)

**Milestone:** M7.3, the third sub-milestone of **Phase 2.5 — Parity & Polish**, following M7.2 (UI shell, shipped v0.4.0) and preceding M7.4 (Tools).

**Goal:** Give Pluton a place to *see and edit what is in the model*, rather than only what is on screen — a Blender-style right panel pairing a model Outliner with an icon-tabbed Properties editor, and the per-instance hide/rename state that an Outliner needs to be worth opening. Ship as **v0.5.0**.

**Shape:** Python-only. No kernel change (`ctest` stays 82/82). Two new undoable commands, two new `Instance` fields, and a document-format bump (`SCHEMA_VERSION` 3 → 4, additive — v3 files still open).

---

## Context: why this milestone exists

After M7.2, Pluton looks like an application. It still offers no way to answer two questions a modeler asks constantly:

**"What is in this model?"** The only view of the scene graph is the viewport itself. A group nested three levels down inside another group is reachable only by double-clicking into it through every ancestor, and there is no way to see that it exists without finding it in 3D first.

**"What is this thing I selected?"** Nothing reports the type, name, dimensions, tag, or material of the current selection. [#73](https://github.com/Parrow-Horrizon-Studio/pluton/issues/73) has tracked the Entity-Info half of this since M5c; M7.2 shipped its context-menu half and deliberately left the panel half open.

There is also a capability gap underneath both. **Visibility is tag-only.** To hide one wall you must invent a tag, assign it, and toggle it — and doing so hides every other object sharing that tag. `Instance` has no `hidden` flag and no `name`, so the two operations an Outliner exists to perform have nothing to write to.

Finally, the three per-tool option bars (Wall, Door/Window, Roof) sit in the central column above the status bar, appearing and vanishing as tools are armed and pushing the viewport around as they do. They belong in a panel.

`main_window.py` is 1410 lines and [#100](https://github.com/Parrow-Horrizon-Studio/pluton/issues/100) is open against it. This milestone adds a panel with five tabs, two-way selection sync, and context navigation. It must not simply pile that on.

## 1. Scope

### 1.1 The shape

The right side becomes **one dock**, `PropertiesDock`, holding a vertical `QSplitter`:

```
┌─ Outliner ───────────────────┐
│ ▾ Model                      │
│   ▾ Group "North Wing"    👁  │
│       Wall                👁  │
│       Wall                🚫  │  ← hidden
│     Roof                  👁  │
├─ Properties ─────────────────┤
│ [🔧][ℹ][🎨][🏷][🎬]          │  ← icon tab strip
│                              │
│  (active tab's page)         │
└──────────────────────────────┘
```

**Five tabs**, replacing three docks and three option bars:

| Tab | Contents |
|---|---|
| Tool Settings | the active tool's options, or "No settings for this tool." |
| Entity Info | the current selection's attributes (§1.4) |
| Material | today's `MaterialsDock` body |
| Tags | today's `TagsDock` body |
| Scenes | today's `ScenesDock` body |

`MaterialsDock`, `TagsDock` and `ScenesDock` stop being `QDockWidget`s and become plain `QWidget` pages. All three already build their UI into a `container` widget that the dock merely wraps, so the change is to the wrapper, not the contents.

The central column loses the three option bars and keeps viewport + bottom bar.

**Consequence for the View menu.** `View ▸ Materials` / `Tags` / `Scenes` are **not** `ActionSpec`s — they are `QDockWidget.toggleViewAction()` objects appended to the View menu at `main_window.py:283-288`. When the docks stop being docks, those three actions cease to exist and must be **replaced by three declared `ActionSpec`s** whose handlers show the panel and focus the corresponding tab:

| id | label | handler |
|---|---|---|
| `view_materials` | Materials | `_on_show_material_tab` |
| `view_tags` | Tags | `_on_show_tags_tab` |
| `view_scenes` | Scenes | `_on_show_scenes_tab` |

`PropertiesDock` is still a `QDockWidget`, so it keeps a real `toggleViewAction()` for `View ▸ Properties Panel`.

### 1.2 Model layer

Two fields on `Instance` (`__slots__` grows by two):

```python
self.name: str = ""        # "" -> the row falls back to definition.name
self.hidden: bool = False
```

`name` is per-**instance**, not per-definition, so renaming one instance of a shared component does not rename its siblings. The definition name remains visible in Entity Info. An empty name renders as `definition.name`, so an un-renamed row still reads "Wall" or "Roof".

Two commands, both following `TagInstancesCommand`'s shape — capture prior state per instance in `do`, restore it in `undo`:

```python
# commands/visibility_commands.py
class HideInstancesCommand(Command):
    name = "Hide"                     # or "Unhide", set from the constructor
    def __init__(self, instances, hidden: bool) -> None: ...

# commands/naming_commands.py
class RenameInstanceCommand(Command):
    name = "Rename"
    def __init__(self, instance, new_name: str) -> None: ...
```

Visibility filtering is **one added condition on three existing lines**, but the three are not identical. Only `_traverse_visible` carries the active-path bypass:

```python
# Model._traverse_visible — recurses through the whole graph, so an entered
# instance must survive the prune or you could not edit inside it.
if inst.id not in active_ids and (inst.hidden or not self.tags.is_visible(inst.tag_id)):
    continue

# Model.pick_instance and Model.pick_face_local — both iterate
# self.active_context.children only. A child of the active context is by
# definition not itself entered (entering it would make it the active
# context), so there is no bypass to preserve.
if inst.hidden or not self.tags.is_visible(inst.tag_id):
    continue
```

The bypass in `_traverse_visible` means a group you have entered stays visible and editable even when hidden — the same rule tags already follow, so there is no second concept to learn.

### 1.3 Hide / Unhide actions

Three new `ActionSpec`s, which M7.2 explicitly withheld for this milestone:

| id | label | shortcut | enabled when |
|---|---|---|---|
| `edit_hide` | Hide | `H` | selection contains ≥1 instance |
| `edit_unhide` | Unhide | `Shift+H` | selection contains ≥1 hidden instance |
| `edit_unhide_all` | Unhide All | — | any instance in the active context is hidden |

`H` and `Shift+H` are both free: the 18 tools hold `Space E B L R C G A P M Q S T I N W D O`, and the only other `Shift` binding is `Shift+Z` (Zoom Extents).

Declaring them yields Edit-menu entries, context-menu entries and enablement rules from the existing registry.

**Unhide All is not optional.** A hidden object cannot be right-clicked, so without it the Outliner is the only way back and closing the panel strands the geometry.

### 1.4 The pure layer

Three functions and two dataclasses, none importing Qt, all testable without a `QApplication`.

```python
# model/model_queries.py — joins select_all_ids and model_bounds

@dataclass(frozen=True, slots=True)
class OutlinerRow:
    instance_id: int
    depth: int                 # indent level; root children are depth 0
    label: str                 # instance.name or definition.name
    is_component: bool         # not definition.is_group -> different row icon
    hidden: bool               # this instance's own flag; drives the eye toggle
    inherited_hidden: bool     # an ancestor is hidden
    tag_hidden: bool           # its tag is off
    on_active_path: bool       # the entered-context chain

def outliner_rows(model) -> tuple[OutlinerRow, ...]:
    """Depth-first, parents before children — the render order of the tree."""

def instance_path(model, instance_id: int) -> tuple[Instance, ...] | None:
    """Root-first ancestor chain ending at instance_id, or None if unreachable."""
```

**Selection is deliberately absent from `OutlinerRow`.** The widget highlights from `Selection.instances` directly. Rows then change only on *structural* edits, while selection changes many times a second during a box-select drag — folding it in would rebuild the whole tree on every mouse move to apply a highlight Qt can apply itself.

**The three dimmed states stay separate** rather than collapsing into one `visible: bool`, because the eye toggle only controls `hidden`. A row dimmed by `tag_hidden` will not come back when its eye is clicked, and rendering the two identically would misrepresent what the click does.

`instance_path` returns real `Instance` objects because `Model.enter` appends one instance at a time and `revalidate_active_path` checks each against its parent's `children`.

**The tree's "Model" root is not a row.** `outliner_rows` yields only instances, so the root context has no entry — the widget renders a static top-level item labelled with `model.root.name` and parents depth-0 rows under it. Giving the root a synthetic `OutlinerRow` would mean an id that matches no `Instance`, which every consumer would then have to special-case.

```python
# model/entity_info.py

@dataclass(frozen=True, slots=True)
class EntitySummary:
    kind: str                          # "Group" | "Component" | "Edge" | "Face"
                                       # | "Dimension" | "Label" | "Mixed" | "Nothing"
    count: int
    name: str | None                   # instance name, "" when unnamed
    definition_name: str | None
    child_count: int | None
    edge_count: int | None
    face_count: int | None
    size: tuple[float, float, float] | None   # world AABB extents, metres
    length: float | None               # single edge only
    area: float | None                 # single face only
    tag_id: int | None                 # common tag, None when mixed
    material_id: int | None            # common face material, None when mixed
    hidden: bool | None                # None when mixed

def entity_summary(model, selection) -> EntitySummary: ...

# model/model_queries.py
def selection_bounds(model, selection) -> tuple[np.ndarray, np.ndarray] | None:
    """World AABB of the selected instances, reusing model_bounds' walk."""
```

`entity_summary` returns numbers and ids, never formatted strings. Formatting happens in the widget via `format_length` / `format_area`, so switching metric↔imperial re-labels the panel with no model involvement — the rule M7d set for dimension text.

`selection_bounds` measures **actual transformed vertex extents**, not a local AABB scaled by the matrix, which is wrong as soon as anything is rotated.

**What Entity Info can edit.** Four fields, each writing through a command that already exists or is defined above — the panel introduces no new model surface of its own:

| Field | Command | Applies to |
|---|---|---|
| Name | `RenameInstanceCommand` | a single selected instance |
| Tag | `TagInstancesCommand` | any instance selection |
| Hidden | `HideInstancesCommand` | any instance selection |
| Material | `PaintFaceCommand` | any face selection |

Everything else in `EntitySummary` is read-out. A field is disabled rather than hidden when the selection does not support it, following the rule `context_menu.is_enabled` already sets: an entry that keeps its position is learnable, one that reflows is not. Name is single-instance only because a shared name across a multi-selection has no meaning.

**One genuinely new unit function.** `units.py` has `format_length` and `format_angle` but nothing for area, so M7.3 adds:

```python
def format_area(square_meters: float, units: Units) -> str:
    """m² in metric; ft² in imperial. Two decimal places."""
```

### 1.5 The panel

```python
# ui/panels.py — Qt-free, like actions.py

@dataclass(frozen=True, slots=True)
class TabSpec:
    id: str
    title: str      # tooltip and accessible name
    icon: str       # icon asset stem

PROPERTIES_TABS = (
    TabSpec("tool_settings", "Tool Settings", "tab-tool-settings"),
    TabSpec("entity_info",   "Entity Info",   "tab-entity-info"),
    TabSpec("material",      "Material",      "tab-material"),
    TabSpec("tags",          "Tags",          "tab-tags"),
    TabSpec("scenes",        "Scenes",        "tab-scenes"),
)
```

Unlike `actions.py`, a tab appears in exactly **one** surface, so this table collapses no duplication. It earns its place for one narrower reason: it makes "every tab id maps to an icon asset that exists" a test rather than a blank button someone notices in a screenshot. M7.2 hit that class of bug — `ui_builder.build_action` carries a `KeyError` fallback because of it. `panels.py` carries the same "importing it loads zero PySide6 modules" test `actions.py` has.

Page construction stays in the Qt module as an id → constructor mapping.

**New icon assets (8),** through M7.2's existing `icons/` pipeline and palette recolor: the five tab icons above, `outliner-group` and `outliner-component` for row types, and `visible` / `hidden` for the eye column.

### 1.6 Tool Settings

`WallOptionsBar`, `OpeningOptionsBar` and `RoofOptionsBar` are **reparented verbatim** into a `QStackedWidget` inside the Tool Settings page. No rewrite. `MainWindow._sync_option_bars` changes from show/hide to select-page, and tools with no options select a "No settings for this tool." page.

**Arming a tool that has settings auto-switches the panel to Tool Settings,** and nothing switches it back. Today, picking the Wall tool makes thickness and height appear; if the panel sat on Entity Info they would silently not, which is a regression dressed as a layout change. Only 3 of 18 tools have settings, so this fires rarely.

### 1.7 Outliner interaction

**Clicking a row selects that instance and moves the active path to the row's parent chain.**

A single click can therefore exit a group you were editing. The alternative is worse: `Selection` is only meaningful inside the active context — that is what every tool, the renderer's dim pass, and `pick_selectable` assume. Selecting a nested row *without* re-rooting would place an id in the selection that the active context cannot see, giving a highlighted-but-untouchable object. SketchUp re-roots for the same reason. The breadcrumb and the dim pass both update, so the change of context is visible rather than silent.

**Double-clicking a row enters that instance**, equivalent to double-clicking it in the viewport.

Both walk `instance_path` and call `Model.enter` per ancestor.

**Refresh triggers:**

| Change | Response |
|---|---|
| Command executed / undone / redone | full row rebuild (M6a's `CommandStack` change-listener) |
| Enter / exit a context | full rebuild, expand to the active path |
| Tag visibility toggled | full rebuild (`tag_hidden` moved) |
| Document New / Open | rebuild and rebind libraries |
| `Selection.version` changed | **highlight only**, no rebuild |
| Mouse move | nothing |

An `_applying` guard, the same shape as `TagsDock._rebuilding`, breaks the tree → selection → tree loop.

### 1.8 The bottom bar

`StatusBar` splits from one `QLabel` into three fields in a `QHBoxLayout`:

```
 Line · Endpoint · Model ▸ North Wing      X 2400  Y 1200  Z 0     Measurements [ 3600 ▏]
 └─ prompt (stretch) ──────────────────┘   └─ coordinates ─┘       └─ labelled field ───┘
```

The prompt keeps today's joined tool / snap / breadcrumb / status / selection text. Coordinates are unit-aware via `format_length`. The Measurements box remains a **display** driven by the existing type-anywhere key capture — not a `QLineEdit`, no focus, no chance of stealing keystrokes from the viewport. It stops being a run of text a user has to already know about.

**Known limitation:** coordinates read from `ViewportWidget._snap_for_event`, which only runs while a tool is active. Pressing Esc to disarm blanks the readout. Computing an inference point on every mouse move regardless would cost work on every event to serve a state users pass through rather than sit in.

### 1.9 `main_window.py`

**Task 1, before any panel work:** extract the selection, visibility and naming handlers M7.3 touches into `ui/selection_controller.py`, and let each panel own its own wiring rather than `MainWindow` reaching into it. A pure move with no behavior change, gated on the full suite staying green.

This does **not** close [#100](https://github.com/Parrow-Horrizon-Studio/pluton/issues/100) — the file/save/import and group-operation handlers stay. It stops M7.3 making the file worse.

## 3. Testing

**Pure, headless — no `QApplication`:**

- `outliner_rows`: depth and ordering; label fallback when `name` is `""`; `inherited_hidden` propagating down a subtree while `hidden` stays own-flag; `tag_hidden` independent of both; a component appearing once per instance
- `instance_path`: nested, root-level, and unreachable ids
- `entity_summary`: each selection kind, mixed, and empty
- `selection_bounds`: correct under a rotated instance transform
- `format_area`: metric and imperial
- `panels.py`: ids unique, every icon stem resolves, importing loads zero PySide6 modules

**Commands:**

- hide/unhide and rename through undo → redo → undo
- a hidden instance absent from `traverse_visible`, `pick_instance`, `pick_face_local`
- the active-path bypass still rendering an entered hidden group

**Persistence:**

- v4 round-trip preserving names and hidden flags
- **a v3 file opens** with both fields defaulted

**Qt wiring:**

- row click re-roots the active path and sets the selection
- viewport selection highlights the row without a rebuild
- double-click enters the instance
- the tab strip builds all five pages
- arming Wall / Door-Window / Roof selects the matching Tool Settings page
- each reparented option bar still writes to its tool's attribute
- each Entity Info field dispatches its command and is undoable; a field is disabled, not hidden, when the selection does not support it

**Regression:** the full existing suite green, plain and under `CI=true`; `ctest` unchanged at 82/82.

## 4. Decisions

- **D1 — One dock, not two.** Outliner and Properties share a splitter rather than tabbing against each other; seeing the tree while editing a selection's attributes is the point.
- **D2 — Absorb Materials, Tags and Scenes as tabs.** Leaving them as docks would put two tab strips on the right edge — Qt's dock tabs plus the Properties icon tabs — which is the confusion a single properties editor exists to avoid.
- **D3 — Per-instance `hidden`, not per-definition and not tag-proxied.** Tag-proxying would hide every object sharing a tag and could not hide an untagged one.
- **D4 — Per-instance `name` with definition fallback.** The only option where renaming one instance of a component does not rename its siblings.
- **D5 — Loose geometry cannot be hidden.** Hiding individual edges and faces needs a per-entity sidecar on `Scene` plus renderer and picking filters — the same shape as the deferred loose-geometry tagging in [#69](https://github.com/Parrow-Horrizon-Studio/pluton/issues/69), and large enough to distort this milestone.
- **D6 — Selection stays out of `OutlinerRow`.** Structural rebuilds are rare; selection changes are continuous during a drag.
- **D7 — Clicking a row re-roots the active path.** Required for the selection to be meaningful to the tools, renderer and picker.
- **D8 — The Measurements box stays a display.** Making it a real focusable field risks capturing keystrokes the viewport needs; the visual treatment delivers the discoverability without the risk.
- **D9 — `QTreeWidget`, not `QAbstractItemModel`.** `QAbstractItemModel.parent()` must return one unambiguous parent per index, and Pluton shares a `Definition` across many component instances; the index bookkeeping must key on instances, and getting it subtly wrong crashes rather than misdraws. Correct at scale, wrong for now — and `outliner_rows` ports behind it cleanly when M10 needs it.
- **D10 — A scoped `main_window.py` extraction, not a full one.** Closing [#100](https://github.com/Parrow-Horrizon-Studio/pluton/issues/100) outright is a large mechanical diff across code six milestones depend on, landing before the feature work rather than alongside it.

## 5. Out of scope

- **Numeric transform fields** in Entity Info → M7.4. Decomposing an arbitrary 4×4 into position/rotation/scale is ambiguous under shear or non-uniform scale, so the fields would sometimes disagree with the matrix they came from.
- **Loose-geometry (edge/face) hiding** → with [#69](https://github.com/Parrow-Horrizon-Studio/pluton/issues/69).
- **`QAbstractItemModel` + `QTreeView`** → M10.
- **Outliner drag-to-reparent.** Moving an instance between contexts is a model operation needing its own command and its own undo semantics.
- **Outliner search / filter box.**
- **Locking** (a `locked` flag alongside `hidden`). Plausible neighbour, no demand yet.
- **Per-instance visibility in Scenes.** `SavedView` captures tag visibility and render style; extending it to per-instance hidden state is a Scenes change, not an Outliner one.

---

## 6. Risks

- **Reparenting three shipped widgets** is the likeliest breakage — the option bars move from a `QVBoxLayout` to a `QStackedWidget` and their tool bindings must survive. Mitigation: the classes move verbatim, and each keeps a test that edits a field and asserts the tool's attribute changed.
- **Three docks becoming pages invalidates every saved layout.** `WINDOW_STATE_VERSION` 1 → 2 makes Qt discard stale blobs cleanly rather than half-restore them.
- **Sync loops** between tree and viewport selection. Mitigation: the `_applying` guard, and a test asserting a viewport-driven selection change does not rebuild rows.
- **`main_window.py` growth.** Mitigation: D10's scoped extraction as Task 1.
- **Schema bump.** Mitigation: additive fields plus an explicit "a v3 file opens" test.
